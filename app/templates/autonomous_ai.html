What this is: the model decides both when to enter AND when to exit, entirely on its own judgment -- no ADX, no EMA/Supertrend/RSI, no CPR, no TradingView signal of any kind. It sees only the current price and today's trading range, the same numbers a human glancing at the dashboard's price ticker would see. Every open position is re-asked, every ~5 minutes, whether to hold or exit -- an EXIT answer really does close the trade immediately, it isn't just logged.

What this is not: proven to work, or even a new kind of question this project hasn't already asked. A two-year backtest already found that a 45-minute price-drift rule -- the same class of input this strategy is given -- has zero positive directional edge on either index, at any horizon; six of sixteen drift bands were reliably negative. Genuine LLM judgment isn't the same as a mechanical rule, so that finding doesn't automatically apply here -- but it means this page's own real results are a fair, still-open test, not a foregone conclusion either way. Every open position also carries a wide backstop stop/target (a safety net, not the intended exit -- the model's own per-cycle decision is meant to act first). No new entries after 3:00 PM IST, and every open position is squared off unconditionally at 3:00 PM regardless of what the model says -- an earlier, dedicated cutoff for this strategy specifically, not the later time every other strategy in this app uses. Paper trading only -- no live-order code path exists for this strategy.

Two more mechanical safety nets, added 3 Sep 2026, both checked before the model is ever asked: a stagnation exit closes a position that has sat 60+ minutes within ±5% of entry, so a flat trade doesn't just keep running until 3 PM -- built after a real trade sat open 4h44m at only +2.27% peak gain before the model's own exit call finally fired at -11.24%. Separately, an admin-toggleable giveback-ratio stop (currently on a 2-week live trial, off unless enabled from Settings > General) protects part of a real gain once a trade's peak clears 12% above entry, so it can't fully round-trip back to a loss. Neither replaces the model's own judgment as the intended exit -- both are backstops, same as the wide stop/target above.

Cost note: re-asking the model every cycle for every open position is real, ongoing API spend beyond a normal one-shot entry decision -- accepted deliberately for this strategy, not something every strategy in this app does.
