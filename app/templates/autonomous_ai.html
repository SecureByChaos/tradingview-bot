What this is: rebuilt 3 Sep 2026 around a real deterministic feature engine -- ADX(14), EMA9/21 trend regime, and an intraday VWAP computed from a futures contract's real volume (index instruments themselves report zero volume, so this is the first VWAP anywhere in this app). Two hard Python gates run before the model is ever asked: no entry during CHOP_ZONE (11:15 AM–1:30 PM), OPENING_VOLATILITY (before 9:30), or SQUARE_OFF_ZONE (3:00 PM on); and no entry when ADX is below 18. Above that floor, the model still makes the actual call -- ADX ≥ 20, spot strictly above/below VWAP, and no extension into PDH/PDL are its own stated criteria, not a second Python gate. Every open position is re-asked, every ~5 minutes, whether to hold or exit -- an EXIT answer really does close the trade immediately.

Exit matrix, checked in order before the model is asked, each one closing the trade immediately and skipping the LLM call if it fires: a session-close warning at 15 minutes to square-off; a fixed-width peak-giveback (exits once a ≥20% peak gain gives back 8 points); a break-even violation (exits if a ≥15% peak gain has fallen back to ≤1%); a 25-minute stagnation exit for a trade stuck within ±5% of entry; and a structural-invalidation exit if the underlying's spot-vs-VWAP relation flips against the held side. Only if none of those fire does the model get a real HOLD/EXIT decision. The hard stop-loss and profit target (now 15%/30% nominal, tightened from 35%/50%) are enforced separately and faster still, every 30 seconds, by the same shared mechanism every other strategy's backstop uses. The unconditional 3:00 PM IST square-off is unchanged and always wins.

What this is not: proven to work. This rebuild implements an external design document as specified, including an ADX gate and a fixed-width trailing stop this project had previously tested and moved away from for OTHER populations (AI Origination's own decisions, and a 2024-era rule-based holdout) -- done deliberately, on explicit instruction, after the tradeoffs were laid out. Those earlier findings don't transfer directly to this module's own real trades, which is exactly why this page's own numbers, not a prior finding, are the honest answer to whether this construction works. Paper trading only -- no live-order code path exists for this strategy.

Cost note: re-asking the model every cycle for every open position is real, ongoing API spend beyond a normal one-shot entry decision, and the feature engine now also spends a futures-contract candle fetch per index per cycle for VWAP -- accepted deliberately for this strategy, not something every strategy in this app does.
